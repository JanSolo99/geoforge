# Create Spatial Sampling Locations — public ArcGIS Pro 3.7 controls

Reference: https://doc.esri.com/en/arcgis-pro/latest/tool-reference/data-management/create-spatial-sampling-locations.html

`probe.py` saved the immutable `testdata/geoproc/ssl_areas.shp` before the controls.
Three disjoint rectangles have areas100/300/200, strata A/A/B and population2/3/5.
Do not recreate this fixture. `probe_formats.py` repeats allocation controls with
an independently copied disposable FileGDB source. `probe_grid_precision.py` reads
saved systematic polygons and checks a nonempty COMPLETELY_WITHIN case.

Observed random/stratified contracts:

- RANDOM dissolves the whole study area and creates a global count (default100).
  No input attributes are retained; output has CID integer width10, all1.
- STRAT_POLY makes each input polygon a stratum. STRAT_ID dissolves polygons by the
  chosen integer/text field. EQUAL uses num_samples_per_strata; FIELD sums the
  nonnegative integer population. EQUAL/FIELD use sequential CID1,2,... .
- PROP_AREA and PROP_FIELD allocate a global num_samples using largest remainders,
  with CID0,1,... . This offset is the same for shapefile and FileGDB sources and
  is not the original input OID. Examples: area weights1/3/2 with7 ->1/4/2;
  populations2/3/5 with9 ->2/3/4; equal ID-stratum populations with9 ->5/4.
- Spacing is global for RANDOM, per stratum for stratified designs. Infeasible
  spacing reduces the count and warns110547. Zero/negative requested counts fail
  000531; missing conditional ID field fails000530; no locations fails110544.

Systematic behavior:

- Reuses Generate Tessellation's five supported shapes with explicit area units.
  Lower-left centroid anchor, bottom-up row order and GRID_ID retained. Output
  includes Shape_Length/Shape_Area (Shape_Leng in shapefiles). Centroid output also
  has1-based ORIG_FID of the unfiltered grid. Whole cells are returned, not clipped.
- POINT uses centroid membership; POLYGON supports centroid, completely-within and
  intersects inclusion. Empty grid selection returns110544. The public failure
  left an empty shapefile family; native failures leave no new output and preserve
  existing outputs. Failed-reference comparisons check the primary error, not
  identical filesystem side effects.
- The first reference run exposed a precision stage: non-square bin measurements
  differ from ideal-area geometry. Public polygon outputs have vertices on the
  standard FileGDB XY grid; an intermediate FileGDB storage step is inferred from
  those coordinates and measurements. Native now
  snaps using default XY tolerance/10, then measures the stored shape and selects
  centroids with XY tolerance. The existing comparison/tolerances were retained.
  A boundary hexagon exposed numerical drift in a strict centroid predicate.

23 ssl_* cases (19 successes,4 refusals) are generated by make-arcgis-reference.py.
Random/stratified cases use a dedicated `stochastic_sampling` contract: exact schema,
CRS and counts per CID plus independent stratum membership, uniqueness and spacing.
Systematic cases retain the existing exact field/geometry comparator. Prior cases
are unchanged. Independent public ArcGIS reading of native outputs is performed by
prepare_native.py/probe_native.py; validation outcomes/logs are in docs/HANDOFF.md.
The initial native output root is retained for precision research; final corrected
outputs use a separate v2 root.

Scope/gaps: projected-meter controls were validated. Other CRS units/resolution
domains are unverified. Polygon study areas only, planar random and stratified designs and
systematic bins with explicit area units. Raster study areas/strata, CLUSTER, H3
and bin-count optimization are explicitly unsupported. Native SplitMix64 seed0 is
reproducible but does not reproduce ArcGIS random streams. Bounded rejection may
underfill dense/thin strata. Extent/output-CRS/random-number environments, selections,
custom XY resolution/domains, engineering/geographic CRS, Z/M/curves, NULL strata/
population values, unusual ID collation/ties and advanced schemas are unverified.
Curves/nonfinite coordinates are refused. Population NULL is treated as0; negative
population values are refused. Random sample requests are capped at1million; the
existing tessellation cap is5million candidate cells. Rows/groups are held in memory.
Systematic FileGDB derived-field flags/class metadata are unverified. No runtime
GDAL dependency or Esri SDK. Random Points changed only by adding a shared private
polygon-sampling helper; its landed behavior is preserved.
