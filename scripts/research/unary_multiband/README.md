# Uncached integer multiband unary math

ArcGIS Pro 3.7 is the geoprocessing oracle. GDAL only creates/reads TIFF storage.
21 private controls cover Abs/Negate/Square across six integer types, NoData
masks in each band, signed/unsigned overflow boundaries, and reversed I16
band order. Every ArcGIS result retains both bands. The baseline native output
retains only the first band in all 21 cases (baseline.json).

The source recipe verifies every stored sample/type/NoData by read-back and
requires no cached extrema or PAM sidecars. Uncached type planning uses the
existing single-band storage rules, so each band shares an output type/marker.
NoData propagates per band; U32 Negate wraps through signed32 and Square overflow
becomes missing, as in the existing single-band controls.

Twelve initial private cached/uncached I16 controls (cached_observations.json)
showed output planning needs both band ranges, regardless of order. The original
reader retained only band0; that was insufficient for cached integer support.
The subsequent `cached/README.md` checkpoint unions stored extrema without
scanning samples and adds36 typed controls. Stale per-band caches remain a
separate compatibility question.

Recreate format inputs in a fresh directory:

```
/usr/bin/python3 scripts/research/unary_multiband/recreate_inputs.py /tmp/new-unary-multiband
```

The private probe.py uses /tmp/unigis-integer-multiband/typed. probe_cached.py
uses four private I16 controls one directory above it. To recreate those, use
the format recipe in a fresh directory, copy i16.tif to forward_raw.tif and
forward_cached.tif, and i16_reverse.tif to reverse_raw.tif and reverse_cached.tif
in /tmp/unigis-integer-multiband. The cached probe calls ArcGIS CalculateStatistics
only for the *_cached copies before running math. These probes
never run on repository inputs, so ArcGIS cannot mutate committed source caches.
Saved `umrawmulti_*` goldens were generated by ArcGIS using the repository inputs:

```
uv run -q --with 'mcp>=2' python scripts/make-arcgis-reference.py 'umrawmulti_*'
/usr/bin/python3 scripts/research/unary_multiband/compare_native.py
/usr/bin/python3 scripts/research/unary_multiband/compare_native.py /tmp/new-unary-multiband
```

All 21 comparisons pass with both repository and freshly recreated inputs
(native_after.txt, recipe_verification.txt). Comparisons cover every band's exact
samples/mask/type/NoData, statistics, grid, semantic CRS and PAM placement. The
workspace reference suite additionally applies its standard raster checks.
source_verification.json confirms every repository source is byte-identical to
its original private control and unchanged after reference generation, with no
new source PAM caches. The Rust change only extends the existing dispatcher to
uncached integers; existing per-band storage/overflow rules are reused.

Full workspace validation is recorded in docs/HANDOFF.md; do not infer a full
suite pass solely from the companion 21-case comparison.


## Refuse unsupported multiband operations safely

Three additional private F64 controls confirm ArcGIS SquareRoot/Ln/Exp retain
both bands (F32 output); native014c027 wrote only band0. guard_probe.py,
guard_observations.json and guard_baseline.json record this evidence. Recreate
its private float64.tif by copying first_full_f64.tif from
 testdata/raster/copy_multicache without its PAM to
 /tmp/unigis-unary-guard-controls before running the bridge probe.

Registered unary tools now explicitly refuse unsupported multiband combinations
before returning an output. The support predicate is shared with the existing
Abs/Negate/Square dispatcher. At this checkpoint cached integer and other unary multiband operators were
refused; subsequent cached/floating support is linked below. Remaining refusals
are native capability limits,
not a claim that ArcGIS refuses these inputs. The low-level local::unary API
expects a supported combination; known callers use the validating registry.

unary_band_safety.rs starts with a valid existing output, then checks seven
unsupported requests return code1 with a clear message and leave every file
byte-identical. Cached integer inputs pair the existing i16.tif pixels with
frozen ArcGIS CalculateStatistics XML from the earlier forward_cached control.
That cache is stored separately as i16_cached_statistics.xml to preserve the
uncached source fixture. Existing full/scoped references cover supported inputs.

Floating SquareRoot/Ln/Exp support follows in `floating/README.md`. Its twelve
positive cases replace those three refusal scenarios; the current guard
regression tests Log2/Sin/RoundUp floats and retains cached integer refusals.

Cached integer support now follows in `cached/README.md`. Its36 positive cases
cover Abs/Negate/Square with valid complete stored ranges. The current guard
regression retains integer SquareRoot/Ln/Exp and float Log2/Sin/RoundUp refusals
and adds malformed later-band cache refusal; all seven preserve existing files.
